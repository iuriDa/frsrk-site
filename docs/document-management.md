# Управление документами

Панель: `/admin/documents`. Ссылка «Управление документами» находится в разделе `/documents`.

## Вход и действия

Используется существующий Supabase Auth: та же почта и пароль, что у редактора календаря. Доступ разрешён только пользователям, для которых существующая функция `is_calendar_editor()` возвращает `true`. Новые роли, пользователи и таблицы Supabase не создаются. Токен и право редактирования проверяются сервером для каждого запроса. Публикуемый ключ не даёт прав редактирования сам по себе.

- «Добавить документ»: название, описание, категория, источник и файл. По умолчанию актуальность требует проверки.
- «Изменить»: редактирование сведений, статуса, номера, даты и редакции. Пустое поле файла сохраняет текущий файл; выбранный файл заменяет его.
- «Удалить»: подтверждение удаления записи из публичного каталога. Старые файлы остаются в серверном хранилище для восстановления из резервной копии, но удалённая запись больше не скачивается через API.
- «Обновить список»: загрузка последних изменений. При конфликте сохранения нужно закрыть старую форму, обновить список и открыть документ заново.

Поддерживаются PDF, DOCX, XLS и XLSX размером до 20 МБ. Проверяются расширение, сигнатура файла и обязательные поля; размер ограничен и для запросов без Content-Length. Это проверка формата, а не антивирусная проверка.

## Хранение

Исходный каталог: `src/content/documents.ts`, исходные файлы: `public/documents/`.
Изменения через панель записываются в `data/document-library/catalog.json`, новые файлы — в `data/document-library/files/`. Каталог содержит только переопределения и отметки удаления: новые документы, добавленные в исходный каталог при обновлении сайта, не теряются.

Папка данных исключена из Git и Docker build context. `npm run dev` и `npm start` используют одну папку проекта. Для отдельного standalone-сервера задайте `DOCUMENTS_DATA_DIR` как абсолютный путь. Оба публичных раздела документов читают каталог при запросе; пересборка после сохранения не нужна.

Перед публикацией на хостинге подключите постоянный диск. Подходит сервер Node.js или один контейнер с постоянным томом; файловая система временных serverless-функций не подходит. Пример запуска собранного Docker-образа:

```bash
docker run -p 3000:3000 --env-file .env.local -v frsrk-documents:/app/data/document-library frsrk-site
```

Для Docker build передайте `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` через `--build-arg`; секретные серверные ключи не требуются.

Резервируйте всю папку данных вместе с исходными файлами сайта. Запись использует блокировку и атомарное переименование. Если процесс аварийно остановился во время записи и осталась `.write-lock`, остановите все экземпляры сервера, проверьте целостность `catalog.json`, затем удалите оставшуюся папку блокировки перед запуском.

Удаление из каталога не удаляет первоначальный файл из `public/documents/`: старые прямые адреса исходных файлов сохраняются. Для полного отзыва уже опубликованного исходного файла нужно отдельно удалить его из public при обновлении сайта. Новые загрузки лежат вне public и доступны только по существующей записи каталога.

## Добавленные файлы

- `polozhenie-evsk-173-2025.pdf`: приказ № 173 от 03.03.2025, 61 страница. В переданном скане исходная редакция. Отмечен как архивная редакция, поскольку опубликован приказ № 510 от 09.07.2025 о внесении изменений: https://publication.pravo.gov.ru/document/0001202507220002 . Файл пользователя сохранён без изменения содержимого.
- `evsk-299-2026.xls`: две вкладки «КМС» и «массовые разряды», приложение № 59 к приказу № 299 от 09.04.2026. Содержимое отличается от старой таблицы, включая возрастные требования. Редакция 2022–2025 оставлена в архиве. Автоматическая сверка файла на storage.minsport.gov.ru недоступна (HTTP 403), поэтому новая таблица помечена «Требует проверки». Реквизиты приказа сверены с карточкой банка Минюста: https://minjust.consultant.ru/documents/60346 .
- `ustav-oo-frsrk.pdf`: 20-страничный скан устава ОО ФРСРК. Файл пользователя сохранён без изменения содержимого и доступен для скачивания в верхнем блоке страницы «О федерации».

## Проверки

`npm run test:documents`: интеграционные проверки настоящих обработчиков API с временным каталогом и имитацией ответов Supabase Auth. Включены права доступа, добавление, скачивание, изменение описания, замена файла, конфликт редакторов, удаление, ограничения форматов и PDF-выгрузка календаря. Тесты не обращаются к настоящему Supabase и не меняют каталог сайта.

Ручная проверка: войти редактором, добавить документ, открыть его на публичной странице, заменить файл, проверить скачивание и удалить запись. Проверить формы при ширине 375, 768 и 1280 px.

## Выгрузка календаря

«Скачать PDF» создаёт PDF-файл с событиями выбранного года (либо всех лет) и включённых видов мероприятий. В файле события идут по датам; события без точной даты остаются в списке с соответствующей пометкой. Документ формируется на сервере в формате A4 с альбомной ориентацией, русским шрифтом, переносами строк и нумерацией страниц.

## Результаты проверки 07.09.2026

- Успешны lint, typecheck, production build и три интеграционных теста.
- Проверены dev-сервер на 3002 и собранная версия на 3012: затронутые страницы и скачивание файлов отвечают HTTP 200. Запросы изменения без входа отклоняются с HTTP 401.
- В браузере скачаны PDF-список из двух мероприятий и PDF-список из одного мероприятия после отключения всероссийских событий. Содержимое файлов проверено; при выборе пустого года кнопка недоступна.
- Страницы календаря, документов, контактов, федерации, реквизитов и входа в панель проверены на ширинах 375, 768 и 1280 px: горизонтального скролла нет.
- Добавление, замена, удаление и защита от конфликтов проверены через настоящие обработчики API в изолированных тестах с имитацией Auth. Вход с реальной учётной записью и полный ручной сценарий редактора остаются для проверки владельцем аккаунта.
