# Аудит муниципалитетов и Supabase — 08.09.2026

## Маршруты и источник данных

- `/municipalities` отображает карту и список из одного клиентского запроса к `training_cities` с вложенными `training_organizations`.
- `/municipalities/admin` использует ту же модель и те же таблицы; после входа разрешает CRUD через RLS.
- `/municipalities/map` и `/where-to-train` перенаправляют на `/municipalities`.
- `/admin/where-to-train` перенаправляет на `/municipalities/admin`.
- старые `/municipalities/[slug]` перенаправляют на `/municipalities?city=<slug>`; статические страницы муниципалитетов и статические записи из `src/content/municipalities.ts` больше не используются.
- показатели муниципалитетов на главной странице рассчитываются из того же ответа Supabase; жёстко заданные числа 18/16/4 удалены.

Страница `/municipalities` остаётся статически собранной оболочкой Next.js, но данные в неё не встраиваются при build и не кэшируются через `revalidate` или `unstable_cache`. Актуальные записи читаются из Supabase после открытия страницы и обновляются по Realtime.

## Запросы

Обычная загрузка выполняет один запрос к `training_cities` с embedded relation `training_organizations`. Выбираются только поля, которые использует интерфейс. Запросов для отдельных городов и N+1 нет.

Изменения города или организации возвращают сохранённую строку через `.select(...).single()`. Интерфейс обновляется ответом базы только после успеха. События Realtime объединяются коротким debounce, чтобы каскадное удаление не запускало несколько одинаковых перезагрузок.

Нужные индексы уже входят в безопасную миграцию:

- `training_cities (active, name)`;
- `training_organizations (city_id, active, name)`;
- уникальный индекс `training_cities.slug` создаётся основной схемой.

## Состояние рабочей базы

Публичное чтение `calendar_events` работает. RPC `is_content_editor()` доступна и возвращает `false` без входа. RPC `is_calendar_editor()` существует и закрыта для анонимного вызова. Полный CRUD через RLS требует сессии редактора.

В рабочей базе отсутствуют:

- `training_cities.territory_type`;
- `training_organizations.organization_type`;
- `training_organizations.organization_type_other`;
- `training_organizations.max_url`.

До добавления этих колонок раздел намеренно показывает реальную ошибку Supabase и не подменяет данные статическим списком. Выполнить в Supabase SQL Editor файл `docs/where-to-train-form-fields-migration.sql`. Он добавляет только отсутствующие поля, ограничения и индексы; таблицы и записи не удаляет.

После миграции проверить:

```bash
npm run check:supabase
npm run test:municipalities
npm run check
```

Полный контрольный CRUD: создать активный тестовый город, проверить маркер и карточку списка, переименовать город, добавить и изменить организацию, затем удалить организацию и город. Тестовые записи после проверки удалить.

## Проверка интерфейса

Изолированная браузерная проверка с одним тестовым ответом Supabase:

- 320 px: ширина документа 320 px, карта 266 × 180 px, один REST-запрос, маркер открывается нажатием и показывает нижнюю панель с городом и организацией;
- 1280 px: карта 760 × 428 px, один REST-запрос, маркер открывает боковую панель;
- в обоих режимах нет горизонтального переполнения и ошибок в console.

Живой контрольный CRUD не запускался: рабочая схема пока не прошла миграцию, а в тестовом браузере нет сессии редактора. Тестовые записи в Supabase не создавались и не оставлены.
